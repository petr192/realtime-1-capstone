# Генератор данных для проекта

Заготовка [generate.py](generate.py) для экспериментов. Генератор можно
адаптировать под свою задачу. Вспомогательный [скрипт](create_stuf.py) поможет создать нужные сущности в базе или топики в кафке.

Нужны uv, just и Python 3.12 или новее. Посмотреть что как:

```bash
just run --help
just preview
```

Заготовка создаёт заказы, позиции, оплаты и полные возвраты. Есть
изменения статуса и удаление неоплаченных заказов. Схема находится в
[shop_tables_ddl.sql](shop_tables_ddl.sql), сценарии и контрольные суммы в
`generate.events`. Можно менять их под себя.

## Загрузка в PostgreSQL

Для PostgreSQL задайте подключение к своей учебной базе:

```bash
export POSTGRES_DSN='postgresql://generator:generator@localhost:5432/project'
just pg-schema
just run postgres --orders 10000 --rate 1000
```

`just pg-schema` создаёт схему capstone и таблицы `orders`, `order_items`,
`payments`. Настройку Debezium он не делает. Существующие таблицы не
мигрируются, данные не очищаются. Можно создать схему и при запуске
генератора флагом `--init-schema`.

## Прямая отправка в Kafka

Для Kafka заранее создайте `capstone.orders`, `capstone.order_items` и
`capstone.payments`:

```bash
just topics localhost:19092 capstone 3
just run kafka \
  --brokers localhost:19092 \
  --orders 100000 \
  --rate 5000 \
  --duplicate-rate 0.05
```

У `just topics` аргументы по порядку: адрес брокера, префикс, число
партиций. По дефлоту это localhost:19092, capstone и 3. Replication factor
равен 1 для стенда с одним брокером. Существующие топики рецепт не меняет.

## Параметры

Основные параметры:

- `--orders`: число заказов; каждый создаёт несколько изменений строк (суммарно эвентов придёт в несколько раз больше).
- `--rate`: изменений строк в секунду, 0 снимает ограничение.
- `--batch-size`: размер пакета; в postgresql пакет выполняется одной транзакцией.
- `--dataset` и `--seed`: идентификатор датасета и seed для повторяемого примера.
- `--paid-rate`, `--refund-rate`, `--delete-rate`: доли оплат, возвратов среди
  оплаченных и удалений среди неоплаченных заказов.
- `--duplicate-rate`: вероятность дополнительной копии события. эта опция только для кафки.

Исторический период и кампании тоже настраиваются; остальные аргументы
смотрите в `--help`. Даты в данных исторические, для замера задержки
отдельно фиксируйте время фактического изменения источника.

## Формат Kafka-сообщений

`just preview` показывает kafka-записи без подключения к сервисам: каждая
JSONL-строка содержит topic, key и value. Key состоит из dataset_id и id
строки; таблица определяется топиком. В теле Kafka-сообщения отправляется
value, key передаётся отдельно:

```json
{
  "event_id": "example_3",
  "op": "u",
  "data": {
    "dataset_id": "example",
    "id": "o000000000",
    "campaign_id": "campaign014",
    "status": "paid",
    "amount_cents": 8224,
    "version": 2,
    "created_at": "2026-01-06T09:42:36.000Z",
    "updated_at": "2026-01-06T09:42:37.000Z"
  }
}
```

`op=c` означает создание, `u` изменение, `d` удаление. Для создания
и изменения в data находится полная новая строка, для удаления только
dataset_id и id. Транспортный повтор сохраняет event_id и всё содержимое
сообщения.

⚠️ **Kafka-режим отправляет не Debezium-события.** Они похожи, но у него свой
формат с event_id, op и data, без before/after. Обработчик Debezium envelope
не сможет читать его без адаптации.

В PostgreSQL-режиме генератор выполняет SQL, а ваш Debezium connector
создаёт настоящий Debezium envelope. Эти преобразования нужно привести к
общей модели. Preview идёт в stdout, прогресс и контрольные итоги в stderr.

## Повторные запуски и проверка

По умолчанию каждый запуск создаёт новый dataset_id. Для нового эксперимента
используйте новый ID: в PostgreSQL повтор прежнего столкнётся с первичным
ключом. В конце успешного запуска генератор покажет ожидаемые суммы для
сверки после обработки всего датасета.
